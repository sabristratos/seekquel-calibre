## What it is, and every rule that governs it

`Seekquel Sync`: the first-party Calibre plugin that pairs by device code and carries shelves, ratings, reviews and reading dates **in both directions** over the backend's `/calibre` surface. **Three switches govern it and all three are on in production, re-measured 2026-08-31**: `Features::CALIBRE_SYNC` closes the server surface, `Features::CALIBRE_INTEGRATION` withholds the entry from the Integrations hub entirely, and `Features::CALIBRE_PROVIDER_LOOKUP` decides whether an unplaceable book may spend the catalogue's shared ISBN quota. The second was a build-time constant until 2026-08-24, on the reasoning that the zip did not exist, and moved to a switch an operator can flip once it did; the third shipped after this line first said "both", which is the reason to read `Features::ALL` rather than a count written here. The help-centre entry moved out of `HELP_HORIZON_ITEMS` into the `integrations` category in the same pass (2026-08-24), with `calibre` and `calibreBooks` copy in all four locales. **At v1.5.0, and the release asset carries no version on purpose.** 1.5.0 (2026-09-08) reports whether the last sync worked, how many books it sent and how slow the server was; failures are kept until the next reachable attempt so the operator can see a broken install without the reader reporting it. 1.4.0 (2026-08-25) is the reader's own fine-tuning, and every part of it is plugin-side: the server was not touched and needs no deploy beyond the version constant. 1.4.1 (2026-08-25) stopped the plugin planting itself in the main toolbar on first run regardless of where the reader put it, and relabelled the button "Seekquel Sync" so it can wrap to two lines. 1.4.2 (2026-08-28) bundles a supplemental root CA so sync no longer fails with a certificate error on a Calibre install whose bundled trust store is stale: falls back to the system store exactly as before if the bundle can't load. **It never loaded that bundle until 1.4.3** (2026-09-02): it resolved the file as `Path(__file__).parent / 'certs'`, and a plugin is a zip whose modules have no path on disk, so every request since logged that it could not be read and the system store was all that was ever trusted. A file inside the zip is read with `get_resources('certs/…')`: which `ruff.toml` had already declared a builtin, the intent being right and the implementation not: and `load_verify_locations(cadata=…)` takes the PEM text with no temp file. The shape to keep: **nothing in a Calibre plugin is a path on disk**, and a fallback that logs instead of throwing is a fallback nobody notices has become permanent. 1.4.3 also **forgets a key the server has refused**: a reader who disconnects Calibre under Settings, Integrations was left with an install still offering to send books and failing every attempt on an invalid key, so an `INVALID_DEVICE_KEY` now clears the stored key and the menu returns to offering to connect. None of them touched the server. **1.4.3 was published on 2026-09-02**, so the permanent download link serves 1.5.0. **Which books get sent is now a Calibre virtual library or saved search** (`scope.py`), because a real library carries manuals, rulebooks and conference papers and sending all of them leaves the reader emptying the Books-from-Calibre queue by hand; **a scope that has since been deleted refuses the sync rather than falling back to the whole library**, which would send exactly what the reader set it up to avoid, and an explicit selection still bypasses it. **The reader names their own status labels**, read and written back, so a column holding `Leyendo` stays one; ours are the fallback and the built-in aliases still apply. **And `Preview a sync` plans both directions and writes nothing**: `plan_book` is what `write_book` now applies, so the preview cannot drift from the write: and it deliberately does not advance the pull cursor, or previewing would cost the reader the very page it showed them. **No column is mapped out of the box any more, the rating included**: it defaulted to Calibre's own star column while the plugin's whole contract is that an unmapped column is never read and never written, so a first sync could write a Seekquel rating over one the reader typed in a column they never chose, and connecting now opens Settings rather than telling the reader to go there. **The plugin is English-only and the translated copy now quotes its labels in English** (`integrations.json` install steps, `helpCenter.json` steps, fr/es/de): a French reader was told to click *Se connecter à Seekquel* on a button that says *Connect to Seekquel*. Calibre's own menus stay translated, because Calibre is; the KOReader copy already had this right. The repo now carries the AST scan for module-scope imports of the gui, preferences, library and db packages (`scripts/check_imports.py`, in CI beside ruff). GitHub resolves `/releases/latest/download/<name>` to whatever the newest release holds under that name, so `seekquel-sync.zip` is a permanent direct download and is what `CalibreSetupController` builds the connect panel's button from; a versioned asset can only be linked through the release page, which leaves the reader to find the file. Releases 1.0.0 through 1.2.2 predate the convention, so rolling back to one leaves that URL answering 404. 1.2.3 was never released and has no tag either; its fixes ship inside 1.3.0. **1.4.0 was tagged and left unreleased**, so the release list and the tag list disagreed for six days: its work reached readers inside 1.4.1, whose own notes say so. It was published from its tag on 2026-08-31 with the unversioned asset, `make_latest` false so the permanent link stays on 1.4.2, and **all eleven tags carry a release**. The lesson is the shape rather than the gap: a tag is not a release, nothing here reconciles the two, and CI cannot, so read the release list rather than the tags before naming a version a reader can install. **The app tells a connected install when it is behind**, beside the download button on the connect panel: Calibre updates plugins from its own index and this one is not in it, so an update is the reader repeating the install and nothing else would ever mention it. Silent until an install has paired and reported a version, and silent on a version it cannot read. **GitHub Actions are absent**: the account billing lock prevents every job from starting, so lint and packaging run locally and every release and asset is created through the GitHub REST API by hand. **GPL-3.0-or-later by necessity**: it loads into Calibre's own process. **The zip's root is the *contents* of `seekquel_sync/`, never the folder**: Calibre resolves a plugin's modules through the import name in `plugin-import-name-seekquel_sync.txt` at the zip root, so a zip built one level up installs as a plugin whose every import fails. `python build.py` writes it; `calibre-customize -a` installs it with no GUI. **It is a library sync, not a reading sync, and that is the whole design difference from KOReader.** Calibre is not a reader: it knows what a book is and what the reader typed about it, and cannot know *when* they read it. So reading position is written as a baseline that moves the reader's place and logs no day's reading, and a rating, review or date is applied field by field with **a missing value never clearing one**: a reader maps only the columns they keep, so reading an unmapped column as a deletion would empty a library on the first sync. **A finished book is never un-finished from Calibre**, because `Read` has already posted to the feed, counted towards a challenge and possibly unlocked a badge. **A book the catalogue cannot place is never invented**, the KOReader rule and the same production incident behind it; it waits on the reader in Settings, Integrations, Calibre, where it can also be set aside for the manuals and conference papers a real Calibre library carries. **Three layers were tested against the running stack rather than only mocked** (2026-08-24): the protocol end to end with curl, the plugin's own api/columns/sync modules driven inside Calibre's Python against a scratch library, and the Qt pairing dialog, settings widget, toolbar menu and every reader-facing message. That pass found two real defects: the pull resource lazy-loading an edition per book, which throws outside production, and the review setting offering one-line columns so paragraphs could be mapped into a status column. **Calibre is blocked by policy for desktop control**, so the GUI itself cannot be driven by an agent; test it through `calibre-debug -e <script>`, which runs inside Calibre's own Python with the plugin importable.
